    Raw signing

    Create a RAW transaction to sign an arbitrary message with a vault account key, for both supported and unsupported assets.

    The examples on this page assume you have an initialised client, as described in Choose an interface. Raw signing is performed through the Create transaction endpoint by setting operation to RAW, and it signs a message you supply rather than building a blockchain transaction for you. For the concepts, use cases and enablement steps, see Raw signing, and for complete worked examples see Raw signing code examples.
    Raw signing is an insecure signing method because bad actors can trick someone into signing a valid transaction message and use it to steal funds. It is a premium feature that is not available in production workspaces by default, so you must contact your Customer Success Manager to enable it, although Sandbox workspaces have it enabled for testing. Policies reject all raw transactions by default, so after it is enabled you must add Policy rules that allow users to initiate, approve and sign raw transactions from specific vault accounts. See Raw signing for details.

    ​
    Raw signing in vault accounts

    In your vault accounts you can sign raw messages for either a natively supported asset or an unsupported asset. The signing key is derived from a BIP44-like derivation path, which you pass either implicitly by giving the vault account and asset or explicitly by giving the derivation path and algorithm. To avoid creating duplicate requests when you retry, set a unique externalTxId on every request, as described in Transaction idempotency.

    ​
    Natively supported asset

    For a natively supported asset you provide the assetId and the source vault account, and Fireblocks derives the signing key from them. The content is the message to sign in hexadecimal format, and you omit the message type because it applies only to typed messages. You can optionally add bip44AddressIndex and bip44change to a message to set the address index and change levels of the derivation path.
    • SDK
    • API
    • CLI
    import { TransactionOperation, TransferPeerPathType } from "@fireblocks/ts-sdk";

const response = await fireblocks.transactions.createTransaction({
  transactionRequest: {
    operation: TransactionOperation.Raw,
    assetId: "BTC_TEST",
    source: {
      type: TransferPeerPathType.VaultAccount,
      id: "<SOURCE_VAULT_ACCOUNT_ID>",
    },
    note: "Raw signing test", // Optional - Free-text note shown in your workspace, not sent to the blockchain
    extraParameters: {
      rawMessageData: {
        messages: [
          {
            content: "<HEX_ENCODED_MESSAGE>",
            // bip44AddressIndex: 0, // Optional - BIP44 address_index path level
            // bip44change: 0, // Optional - BIP44 change path level
          },
        ],
      },
    },
    externalTxId: "<YOUR_UNIQUE_ID>", // Optional - Your unique ID; Fireblocks rejects later requests with the same value
  },
});
console.log(response.data);

    from fireblocks.models.transaction_request import TransactionRequest
from fireblocks.models.transaction_operation import TransactionOperation
from fireblocks.models.source_transfer_peer_path import SourceTransferPeerPath
from fireblocks.models.transfer_peer_path_type import TransferPeerPathType
from fireblocks.models.extra_parameters import ExtraParameters

transaction_request = TransactionRequest(
    operation=TransactionOperation.RAW,
    asset_id="BTC_TEST",
    source=SourceTransferPeerPath(
        type=TransferPeerPathType.VAULT_ACCOUNT,
        id="<SOURCE_VAULT_ACCOUNT_ID>",
    ),
    note="Raw signing test",  # Optional - Free-text note shown in your workspace, not sent to the blockchain
    extra_parameters=ExtraParameters(
        raw_message_data={
            "messages": [
                {
                    "content": "<HEX_ENCODED_MESSAGE>",
                    # "bip44AddressIndex": 0,  # Optional - BIP44 address_index path level
                    # "bip44change": 0,  # Optional - BIP44 change path level
                }
            ]
        }
    ),
    external_tx_id="<YOUR_UNIQUE_ID>",  # Optional - Your unique ID; Fireblocks rejects later requests with the same value
)

future = fireblocks.transactions.create_transaction(
    transaction_request=transaction_request,
)
print(future.result().data)

    import com.fireblocks.sdk.model.*;
import java.util.List;
import java.util.Map;

TransactionRequest transactionRequest = new TransactionRequest()
    .operation(TransactionOperation.RAW)
    .assetId("BTC_TEST")
    .source(new SourceTransferPeerPath()
        .type(TransferPeerPathType.VAULT_ACCOUNT)
        .id("<SOURCE_VAULT_ACCOUNT_ID>"))
    .note("Raw signing test") // Optional - Free-text note shown in your workspace, not sent to the blockchain
    .extraParameters(new ExtraParameters().rawMessageData(Map.of(
        "messages", List.of(Map.of("content", "<HEX_ENCODED_MESSAGE>")))))
    .externalTxId("<YOUR_UNIQUE_ID>"); // Optional - Your unique ID; Fireblocks rejects later requests with the same value

CreateTransactionResponse transaction = fireblocks.transactions()
    .createTransaction(
        transactionRequest,
        null, // Optional - xEndUserWalletId (UUID), only for end-user wallet operations
        null) // Optional - Not used for transactions; use externalTxId in the request body
    .get()
    .getData();
System.out.println(transaction);

  --no-confirm

    Unsupported asset

    For an asset that Fireblocks does not natively support, you pass the derivationPath on each message and the signing algorithm on rawMessageData instead of an assetId. The algorithm is MPC_ECDSA_SECP256K1 or MPC_EDDSA_ED25519, and for testnet assets the coin_type in the derivation path is always 1.
    • SDK
    • API
    • CLI
    import { TransactionOperation, TransferPeerPathType } from "@fireblocks/ts-sdk";

const response = await fireblocks.transactions.createTransaction({
  transactionRequest: {
    operation: TransactionOperation.Raw,
    source: {
      type: TransferPeerPathType.VaultAccount,
    },
    note: "Raw signing test", // Optional - Free-text note shown in your workspace, not sent to the blockchain
    extraParameters: {
      rawMessageData: {
        messages: [
          {
            content: "<HEX_ENCODED_MESSAGE>",
            derivationPath: [44, 0, 0, 0, 0], // Conditional - Required when no assetId is given
          },
        ],
        algorithm: "MPC_ECDSA_SECP256K1", // Conditional - Required with derivationPath. Also MPC_EDDSA_ED25519
      },
    },
    externalTxId: "<YOUR_UNIQUE_ID>", // Optional - Your unique ID; Fireblocks rejects later requests with the same value
  },
});
console.log(response.data);

    About the rawMessageData object

    For the fields you can set on each message, such as preHash, which is required only in Cold Wallet workspaces, see Raw signing objects. A single raw signing request can aggregate a maximum of 127 messages.
    For all request and response schemas, see the Create transaction API reference.
